# Dual-GPU VFIO Passthrough & Host Graphics Management

This repository documents and maintains the configuration, automation scripts, and hardware setup for a dual-NVIDIA GPU workstation running **CachyOS (Arch Linux)** with the **Limine** bootloader.

---

## Hardware Overview

| Component | GPU 1 (Primary / Host) | GPU 2 (Secondary / Passthrough) |
| :--- | :--- | :--- |
| **Model** | NVIDIA GeForce RTX 5090 (GB202) | NVIDIA GeForce GTX 1060 6GB (GP106) |
| **PCI Bus ID** | `0000:81:00.0` (VGA), `0000:81:00.1` (Audio) | `0000:82:00.0` (VGA), `0000:82:00.1` (Audio) |
| **PCI Vendor/Device IDs**| `10de:2b85` (VGA), `10de:22e8` (Audio) | `10de:1c03` (VGA), `10de:10f1` (Audio) |
| **Host Driver** | Proprietary `nvidia` (open-kernel module) | Open-source `nouveau` |
| **Primary Role** | KDE Plasma Wayland, CUDA (ComfyUI, Ollama, Steam) | Secondary display, compute, or VM passthrough via `vfio-pci` |

## Configuration Architecture

### 1. Driver Isolation & Modprobe Rules
To ensure the host proprietary NVIDIA driver only binds to the RTX 5090, the GTX 1060 is explicitly excluded:
- **`/etc/modprobe.d/nvidia-utils.conf`**:
  ```conf
  # Exclude GTX 1060 (82:00.0) from the proprietary NVIDIA driver
  options nvidia NVreg_ExcludedGpus=0000:82:00.0
  ```
- **`/etc/modprobe.d/nouveau.conf`**:
  Allows `nouveau` to load without being blocked by default blacklists, while suppressing unwanted Nova driver variants:
  ```conf
  blacklist nova_core
  blacklist nova_drm
  ```

### 2. Early Kernel Module Loading (Initramfs)
- **`/etc/mkinitcpio.conf`**:
  VFIO modules are placed first in the `MODULES` array so `vfio-pci` has priority when passthrough IDs are passed:
  ```bash
  MODULES=(vfio_pci vfio vfio_iommu_type1)
  ```

### 3. Limine Kernel Command Lines
- **`/etc/default/limine`**:
  Defines specific command lines corresponding to the custom boot entries generated by our post-hook:
  ```conf
  # GTX 1060 Passthrough (10de:1c03, 10de:10f1)
  KERNEL_CMDLINE[linux-cachyos-vfio-1060]=quiet splash rw rootflags=subvol=/@ root=UUID=dfd2b568-1d30-4d0c-b998-dee229a71935 amd_iommu=on iommu=pt vfio-pci.ids=10de:1c03,10de:10f1
  KERNEL_CMDLINE[linux-cachyos-lts-vfio-1060]=quiet splash rw rootflags=subvol=/@ root=UUID=dfd2b568-1d30-4d0c-b998-dee229a71935 amd_iommu=on iommu=pt vfio-pci.ids=10de:1c03,10de:10f1

  # RTX 5090 Passthrough (10de:2b85, 10de:22e8)
  KERNEL_CMDLINE[linux-cachyos-vfio-5090]=quiet splash rw rootflags=subvol=/@ root=UUID=dfd2b568-1d30-4d0c-b998-dee229a71935 amd_iommu=on iommu=pt vfio-pci.ids=10de:2b85,10de:22e8
  KERNEL_CMDLINE[linux-cachyos-lts-vfio-5090]=quiet splash rw rootflags=subvol=/@ root=UUID=dfd2b568-1d30-4d0c-b998-dee229a71935 amd_iommu=on iommu=pt vfio-pci.ids=10de:2b85,10de:22e8
  ```

### 4. Automated Post-Hook: `95-vfio-entries`
Installed at **`/etc/boot/hooks/post.d/95-vfio-entries`** (managed by `limine-entry-tool`).
This script runs automatically whenever kernels are installed or updated, scanning `/boot/${MACHINE_ID}/` and registering the passthrough boot entries into `/boot/limine.conf`.

#### Compatibility Note: `limine-mkinitcpio-hook` >= 1.37.1
In version 1.37.1, upstream removed kernel name suffixes from non-UKI initramfs and vmlinuz files (e.g. `initramfs` and `vmlinuz` instead of `initramfs-${kName}`). The script detects both the modern naming format and the legacy format:

```bash
#!/usr/bin/env bash
readonly LIMINE_FUNCTIONS_PATH=/usr/lib/limine/limine-common-functions
source "${LIMINE_FUNCTIONS_PATH}" || exit 1
initialize_header || exit 1

for kDir in "${ESP_PATH}/${MACHINE_ID}"/*; do
    [[ -d "$kDir" ]] || continue
    kName=$(basename "$kDir")
    [[ "$kName" == *-vfio-* || "$kName" == *-fallback* ]] && continue

    initramfs_path="${kDir}/initramfs"
    vmlinuz_path="${kDir}/vmlinuz"

    # Fallback for older limine-mkinitcpio-hook (< 1.37.1)
    if [[ ! -f "$initramfs_path" || ! -f "$vmlinuz_path" ]]; then
        initramfs_path="${kDir}/initramfs-${kName}"
        vmlinuz_path="${kDir}/vmlinuz-${kName}"
    fi

    [[ -f "$initramfs_path" && -f "$vmlinuz_path" ]] || continue

    limine-entry-tool --add-kernel "${kName}" "${initramfs_path}" "${vmlinuz_path}" "-vfio-1060" --comment "GPU Passthrough 1060" --no-mutex --no-hooks --quiet
    limine-entry-tool --add-kernel "${kName}" "${initramfs_path}" "${vmlinuz_path}" "-vfio-5090" --comment "GPU Passthrough 5090" --no-mutex --no-hooks --quiet
done
```

## Maintenance & Verification

### Updating Limine Boot Entries
After making changes to `/etc/default/limine` or `/etc/boot/hooks/post.d/95-vfio-entries`:
```bash
sudo limine-update
```

### Checking Driver Bindings
Verify which driver is actively controlling each GPU:
```bash
lspci -nnk -d 10de:
```
- Standard boot: GTX 1060 uses `nouveau`, RTX 5090 uses `nvidia`.
- Passthrough boot (`-vfio-1060`): GTX 1060 and its audio controller use `vfio-pci`.

### Checking Current Kernel Command Line
```bash
cat /proc/cmdline
```
